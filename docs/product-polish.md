# 产品打磨实施与验收

本轮实施对应产品建议末尾的四个优先级。沿用 Flask、原生 JavaScript、现有浅色莓红视觉和 CSS 变量，不增加运行依赖。变更涉及超过八个文件，按下列四项验收。

1. 日常控制：Media Session 歌曲信息、播放/暂停、前后切歌和进度；搜索快捷键、列表键盘选择及帮助；按实际数据隐藏空列；右键菜单、音量与播放位置记忆；文件命名与保存目录预设。
2. 选对歌曲：公开来源提供的片段标记与码率；谨慎的疑似片段提示；无损、已下载、片段三个筛选；明确筛选、勾选、播放和下载的作用范围。
3. 版本分组：同名同歌手、同专辑、时长接近的结果分组展开；版本原名与来源始终保留；按片段标记、格式、码率给出默认版本；不修改精确身份，不自动替换播放失败的版本。
4. 简化与信任：独立设置页集中格式和缓存；搜索空态引导、来源最近状态和精简下载确认；中英文 README 快速上手与详细文档分离；应用内只读版本检查及发布页入口。

数据流：

```text
musicdl -> Flask 搜索流 -> SearchModel -> 搜索列表 -> 播放队列
                                              -> 下载预检 -> 下载任务
播放队列 -> audio -> MediaControls -> 系统媒体控件
设置页 -> 本地偏好 / Flask 更新接口 -> GitHub Releases（固定仓库）
```

设计：灰白表面、莓红主操作、系统中文字体；继续使用 4/8/12px 圆角；工具条先呈现筛选与选择范围，列表直接提供操作。版本展开采用原地变化，保留焦点；只使用已有短暂按压和行出现动效，遵守减少动态效果偏好。

验证覆盖正常搜索、流式追加、来源失败重试、筛选无结果、分组展开、版本不误并、已选曲目、播放全部、下载预检、存储失败、媒体接口缺失、更新超时/限流/异常数据，以及桌面和手机布局。使用隔离目录与测试音频进行浏览器验收，真实来源另行实测并记录边界。

回滚只需恢复代码；现有收藏、队列和歌曲身份继续兼容。更新检查访问公共仓库，无需密钥、账号或额外服务。

## 验收记录（2026-10-14）

- `make test`：103 项 Python 与 98 项前端测试通过，合计 201 项。本轮增加 20 项针对性检查，移除已经随首曲摘要删除的封面竞争检查。覆盖格式/来源显示、分组不误并、默认版本、组合筛选、媒体降级与清空状态、位置快照、菜单键、菜单展开边界、流式焦点、更新失败、命名预设与路径边界。
- 浏览器实际完成：9 个来源结果显示为 5 组；展开版本、组合筛选、全选与隐藏勾选计数、清空选择、每组一首播放、收藏、右键与键盘菜单、单来源查找、筛选空态、批量确认与取消。批量摘要显示「5 首 · 4 首直接保存 · 1 首已有 MP3」，不展示零项。
- 使用本地生成的静音音频，实际从 FLAC 转 MP3，按「歌手 - 歌名 / 按歌手」保存，并在本地音乐中找到；重新打开保持暂停，手动播放恢复到保存的 9 秒，音量恢复。浏览器 Media Session 收到曲名和播放状态。
- 设置中的缓存入口、容量、焦点返回、快捷键帮助、关闭启动更新检查后的刷新保留均通过；GitHub 更新请求实测返回当前正式版本。来源健康仅代表当前页面最近一次请求结果。
- 1280px 桌面、820px 平板和 375px 手机无页面横向溢出；手机行操作按钮为 40×40px，来源名保留，快捷键帮助在可视区域内。浏览器错误与未处理 Promise 拒绝记录为空。
- 默认咪咕源联网搜索「周杰伦 晴天」，返回 8 个结果，超时和请求错误均为零；未知码率保持未知。没有使用真实平台音乐完成播放或下载验收。
- 最新源码在独立目录构建 macOS 应用成功；安装包全部前端文件逐一比对源码，版本接口正确；清空 PATH 后通过内置工具导出 MP3（不分目录 / 歌手在前）、原文件保留、实际重启与任务记录恢复、系统废纸篓检查。测试只操作生成文件，临时应用使用独立 Bundle ID 和网页存储。
- Python / JavaScript 语法、`git diff --check`、工作流 YAML 语法与本轮文档本地链接检查通过。Windows validation 已接入新增测试；尚未推送或运行远端工作流。

## 复核

范围与四项建议一致；按深度审查完成安全、结构和异步组合检查。固定更新仓库与超时/缓存、仅保存必要元数据、文件命名白名单、UTF-8 长度/系统保留名、目录与符号链接边界均已检查，无新增依赖、外部账号、自动安装或数据迁移。发现的菜单键兼容、晚到暂停事件、流式主版本切换焦点及内部来源名显示问题均已修复，并有回归覆盖。发布复核补正失败重试遗漏命名/目录预设的问题：扩展原有重试测试，确认旧代码的两个自定义预设子场景失败，修复后连同缺少预设的旧任务兼容场景通过。

Windows 原生交互、实体媒体键/耳机及 VoiceOver / NVDA 朗读未实测。Media Session 的可用操作由系统与内核决定；缺失接口时保留普通播放器功能。macOS 未配置 Developer ID 公证，首次打开说明见 [first-launch.md](first-launch.md)。本轮准备随 v0.9.0 发布，远端构建与附件验收另行记录。
